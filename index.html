训练方法：工程问题驱动

01 · Reproduce

先运行真实代码，建立正确性与性能基线。

02 · Profile

用时间线和硬件计数器定位瓶颈，不凭直觉下结论。

03 · Optimize

修改实现或配置，控制变量做前后对照。

04 · Explain

把指标映射回硬件机制、源码和系统边界。

验收原则：每项优化必须提交环境、命令、原始数据、Profile 证据、假设、对照结果、收益与代价。没有实际运行的项目明确标记“未验证”。

Day 01 · 定位并优化一个慢 GEMM

接手一个能运行但性能未知的矩阵乘法程序。任务不是背 Occupancy 定义，而是建立基线、Profile、提出瓶颈假设、对比优化版本并证明结论。

  1. 运行 naive GEMM，测试多个矩阵规模，记录正确性和稳态耗时。
  2. 用 Nsight Systems 拆分 H2D、Kernel、D2H、同步与 CPU 提交空隙。
  3. 用 Nsight Compute 分析 Launch、Occupancy、Compute/Memory Throughput、Warp Stall、Memory Workload。
  4. 运行 tiled GEMM，对照 Shared Memory 数据复用、寄存器和性能变化。
  5. 对比 pinned memory，必须通过时间线确认是否真正发生 Copy/Compute overlap。
提交物：至少三个矩阵规模的原始数据、一份 NSYS 时间线、一份 NCU 报告、naive/tiled 对照和一页性能归因报告。

隐私边界：源代码、实验文件、Profiling 原始报告和个人进度保留在私有仓库；公开站点只发布课程介绍、路线和公开资料入口。
